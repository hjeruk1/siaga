Flows

Login and session

  1. LoginView posts credentials to /api/auth/login
  2. Backend verifies bcrypt password and signs JWT
  3. Token is stored in localStorage as siaga_token
  4. App calls /api/auth/me on boot and routes by role
  5. Requests attach Authorization: Bearer token

Student administration

  1. Admin/Admin Cabang creates siswa
  2. Backend creates siswa row plus active siswa_enrollment
  3. Scope helpers constrain future reads by cabang, rombel, or wali_siswa
  4. Enrollment changes close old records and create a dated new enrollment

Daily record

  1. Guru/Kepsek/Admin views /api/daily-record/today
  2. Guru saves draft to laporan_harian
  3. Optional photos go through multer memory storage and sharp compression
  4. Publish sets published timestamps and notifies linked wali
  5. Wali opens history/detail and can comment back

Pickup

  1. Gerbang scans penjemput QR
  2. Backend validates active penjemput and student cabang access
  3. Absensi status becomes Menunggu with jam_tunggu
  4. Guru/Admin confirms pulang for selected siswa_ids

Billing

  1. Admin defines biaya_tarif by cabang, tahun_ajaran, jenjang, jenis, nama
  2. Admin/Admin Cabang generates monthly or kegiatan tagihan idempotently
  3. Payments create pembayaran and pembayaran_alokasi rows
  4. Tagihan status moves open, sebagian, or lunas based on allocations
